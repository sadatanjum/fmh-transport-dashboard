Core Features

1

Real-Time SLA Monitoring

Tracks three critical checkpoints: Hub Handover (15-min grace), Van Dispatch (15-min grace), and Warehouse Arrival (varies by hub distance). Each checkpoint independently evaluated.

2

Overnight Rollover Logic

Sophisticated time anchoring algorithm handles operations spanning midnight. A van departing at 22:00 and arriving at 01:30 is correctly calculated as 3.5 hours travel time.

3

Consistency Tracking

Goes beyond simple averages to track frequency (how often late), severity (delay amount), and consistency (spread between best/worst).

4

Dual Dashboard Views

FMH Dashboard for internal suburban hub operations and OSD Dashboard for outside-city linehaul routes. Both share backend infrastructure.

5

Data Quality Framework

Production-grade governance: unmapped hub detection, missing config alerts, implausible travel quarantine, sequence anomaly detection.

6

Performance Optimization

Server-side caching reduces API calls, client-side filtering enables instant updates, payload limiting prevents browser freeze.

Technical Deep Dive

Overnight calculation algorithm

The Overnight Calculation Problem

Challenge: Calculating accurate SLA compliance when operations span midnight. A van departing at 22:00 and arriving at 01:30 looks like it traveled backwards in time.

Solution: Anchor all times to a single "operational day" using a rollover threshold:

// Any time before 12:00 PM belongs to "next day" of operational window function anchor_(min) { return (min < ROLLOVER_ANCHOR_HOUR * 60) ? min + 1440 // Add 24 hours : min; } // Example calculation: // 23:00 → 1380 minutes (same day) // 01:30 → 90 + 1440 = 1530 minutes (anchored to operational day) // Travel time: 1530 - 1380 = 150 minutes ✓

This ensures accurate calculations across the entire 18:00–06:00 operational window.

Lessons Learned

What Worked

Google Apps Script as the stack — Zero friction deployment with no DevOps overhead. Shipped working solution in 2 weeks.

What Worked

Server-side caching — Dramatically improved performance and stayed within API quotas even with frequent refreshes.

What Worked

Data quality panel — Saved countless hours debugging "missing" data. Making exceptions visible built user trust.

Key Takeaway

Design for data quality from day 1 — Bad data will happen; plan for it. Validation, quarantine rules, and visible exceptions are not optional.

Key Takeaway

Cache aggressively — Apps Script execution time limits are real. Server-side caching was the difference between "works" and "production-ready."

Future Improvement

Add automated testing — Current tests are manual; would add unit tests for SLA logic and overnight calculations.
